# 美食

美食是 nanobot 内置的 `food` 工具和 `food` 技能。在 WebUI 或已经配对的飞书私聊里直接说今天吃什么、想要菜谱、要采购清单，或要求保存饮食偏好，助手会通过现有对话能力调用它。这一版不连接外卖平台，也不接入微信。

## 启用

更新到包含美食能力的版本后，重启 gateway。不需要新增配置，不需要额外的 API key，也不需要为了这个功能改 Docker 网络。DeepSeek 或其他已经配置好的模型都通过现有工具调用使用它，美食模块没有单独的模型供应商。

Windows 上的 WebUI 和飞书私聊不用另外安装命令。只有把 `food` 写进 `agents.defaults.disabledSkills` 时，技能说明才不会加载；`food` 工具仍然会注册，人数换算、过敏排除、采购汇总和会话隔离由工具执行。

## 可以怎么说

下面每段都可以直接发给助手。自动化测试锁定的是工具结果，不是某一次模型的原文。

今天吃什么，但先不补充条件：

```text
今天吃什么？
```

助手应只追问几个人吃、有多少分钟、预算按什么把握。它不应追问城市，也不应假设家里几口人或有什么忌口。

条件已经说清：

```text
两个人，有30分钟，预算随便。冰箱里有鸡蛋和番茄，口味清淡。今天想自己做。
```

助手应给出能做的菜和大约时间。外食只应停留在菜系或菜品方向；没有城市时不应出现具体饭店、链接、销量、评价、配送时长或实时价格。

按人数出菜谱：

```text
番茄炒蛋，四个人怎么做？
```

用量应按四个人从家常基准换算，并说明这是估计，不是实测营养或价格。步骤里应有生熟分开或把蛋做熟的提醒。

采购清单，先不扣家里的库存：

```text
帮我把两个人的番茄炒蛋和紫菜蛋花汤合成采购清单。鸡蛋先别扣，我还没确认家里有多少。
```

同名同单位的食材应合并。未确认前不应扣除。

确认后再扣，单位不一致就不要换算：

```text
家里有3个鸡蛋，可以扣除。盐如果一边是克、一边是茶匙，不要合并。
```

保存、覆盖和清除只作用于当前这条对话：

```text
请记住：我喜欢清淡，不吃香菜，对花生过敏。
```

```text
我今天口味想吃花生酱。
```

过敏仍应排除。口味不能把花生从过敏里拿掉。

```text
清除这个会话里的饮食偏好。
```

清除后，新的 WebUI 对话或另一个飞书会话本来也不会看到这些偏好。

## 偏好存在哪里

口味、忌口和过敏保存在当前会话里。同一条 WebUI 对话、同一个飞书私聊会话会保留到之后的回合，重启 gateway 后也还在这个会话中。

新开的 WebUI 对话、另一个飞书会话、其他渠道读不到这份偏好。它不会写入 `USER.md`、`memory/MEMORY.md` 或 `SOUL.md`。从当前对话分支出去的新对话，会在分出时复制当时的偏好，之后两边不再同步。所有渠道共用一个会话时，工具会拒绝保存，避免过敏和忌口出现在其他聊天里。

要改过敏，需要明确说保存一份完整的新列表，或清除。更新只会追加过敏，不会因为一句“今天想吃”就删掉。

## 限制

- 不查询商家，不生成下单、付款、联系商家、发消息或定时任务。
- 没有真实来源时，不提供饭店、实时价格、销量、评价、配送时长或可点击链接。没有城市时不推荐具体本地店。
- 菜谱用量是家常估计。内置菜谱按两人份基准换算；不在内置菜谱里的菜，必须由这一次对话提供基准用量和步骤，并标明这是估计。
- 克和 g 视为同一种写法。千克和克、克和茶匙都不会自动换算。
- 过敏按名称包含关系排除，可能比实际需要避开的范围更宽。例如过敏“鱼”时，名称里带“鱼”的菜也会被避开。
- 这里不判断食疗或医疗效果。生熟交叉污染、海鲜、鸡蛋、剩饭和花生会给出操作上的安全提醒。
- 技能文字不能强迫模型每次都调用工具。模型没调用工具时，上述限制没有被程序执行。下面的测试分得清哪些是程序结果，哪些只是说明文字。

如果开启了 Dream，现有长期记忆仍可能把对话摘要写进工作区的 `USER.md`。美食工具自己不会写这份记忆，也不能替 Dream 做隔离。需要完全隔开家庭成员时，继续使用各自的会话；不要把敏感偏好交给工作区长期记忆。

## 测试说明

`tests/agent/tools/test_food.py` 不调用模型，直接检查工具：缺必要信息时追问什么、四人用量、采购合并和单位冲突、过敏不被口味取消、两个会话互不可见、无商家字段、不产生外部动作。

`tests/agent/test_builtin_food_skill.py` 只检查技能能被加载，以及说明文字里有这些边界。它不是一次真实模型对话。仓库里没有使用真实模型密钥做在线验收。
