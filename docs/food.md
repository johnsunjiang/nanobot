# 美食

美食是 nanobot 内置的 `food` 工具和 `food` 技能。在 WebUI 或已经配对的飞书私聊里直接说今天吃什么、想要菜谱、要采购清单，或要求保存饮食偏好，助手会通过现有对话能力调用它。这一版不连接外卖平台，也不接入微信。

## 启用

更新到包含美食能力的版本后，重启 gateway。不需要新增配置，不需要额外的 API key，也不需要为了这个功能改 Docker 网络。DeepSeek 或其他已经配置好的模型都通过现有工具调用使用它，美食模块没有单独的模型供应商。

Windows 上的 WebUI 和飞书私聊不用另外安装命令。只有把 `food` 写进 `agents.defaults.disabledSkills` 时，技能说明才不会加载；`food` 工具仍然会注册，人数换算、过敏排除、采购汇总和会话隔离由工具执行。

## 可以怎么说

下面每段都可以直接发给助手。自动化测试锁定的是工具结果，不是某一次模型的原文。

今天吃什么，但先不补充条件：

```text
今天吃什么？
```

助手应只追问几个人吃、有多少分钟、预算按什么把握。它不应追问城市，也不应假设家里几口人或有什么忌口。

条件已经说清：

```text
两个人，有30分钟，预算随便。冰箱里有鸡蛋和番茄，口味清淡。今天想自己做。
```

助手应给出能做的菜和大约时间。外食只应停留在菜系或菜品方向；没有城市时不应出现具体饭店、链接、销量、评价、配送时长或实时价格。

按人数出菜谱：

```text
番茄炒蛋，四个人怎么做？
```

用量应按四个人从家常基准换算，并说明这是估计，不是实测营养或价格。步骤里应有生熟分开或把蛋做熟的提醒。

采购清单，先不扣家里的库存：

```text
帮我把两个人的番茄炒蛋和紫菜蛋花汤合成采购清单。鸡蛋先别扣，我还没确认家里有多少。
```

同名而且能换算的质量或体积应合并，例如 1 千克和 500 克合成 1500 克。未确认前不应扣除。不足 1 克的用量保持原值，不会被抬成 1 克。

确认后再扣。克和茶匙、斤和克不能换算：

```text
家里有3个鸡蛋，可以扣除。盐如果一边是克、一边是茶匙，不要合并。
```

保存、覆盖和清除只作用于当前这条对话：

```text
请记住：我喜欢清淡，不吃香菜，对花生过敏。
```

```text
我今天口味想吃花生酱。
```

过敏仍应排除。口味不能把花生从过敏里拿掉。

```text
清除这个会话里的饮食偏好。
```

清除只会去掉口味和忌口。已保存的过敏会留下来，这一版不能从工具里删除。

## 偏好存在哪里

口味、忌口和过敏这份记录保存在当前会话元数据里。同一条 WebUI 对话、同一个飞书私聊会保留到之后的回合，重启 gateway 后也还在这个会话中。飞书群，或无法确认是私聊的飞书会话，不能保存、修改或读取这份记录。

新开的 WebUI 对话、另一个飞书私聊和其他渠道读不到这份元数据。工具不会写入 `USER.md`、`memory/MEMORY.md` 或 `SOUL.md`。这不是端到端隔离：你在对话里说过的原话，仍可能经现有 Dream、历史摘要或会话搜索传播到其他会话。

从当前对话分支出去时，复制的是分支发生时元数据里的当前偏好，不是分支点那句话之前的历史偏好。即使分支点早于保存过敏的那句话，新对话仍会带上当前过敏。分支之后两边不再同步。所有渠道共用一个会话时，工具会拒绝保存。

保存、更新和清除都不能删除已保存的过敏，只能追加。口味不能把过敏拿掉。

## 限制

- 不查询商家，不生成下单、付款、联系商家、发消息或定时任务。
- 没有真实来源时，不提供饭店、实时价格、销量、评价、配送时长或可点击链接。没有城市时不推荐具体本地店。
- 菜谱用量是家常估计。只有内置菜谱会返回食材和步骤。临时菜名、用量或步骤不会变成可执行做法。
- 克和 g、千克和 kg 是同一种写法。千克与克、升与毫升会按 1000 倍换算后合并。茶匙、斤和其他未列出的单位不换算。单行数量超过 100000 会被拒绝。采购行不要和人数一起传。
- 过敏只按菜名、食材和步骤里写出的字做包含判断。它可能比实际需要避开的范围更宽，例如过敏“鱼”时，名称里带“鱼”的菜也会被避开。对不上的词不会被当成同一种过敏原，也没有一份医学同义词表。名称没出现，不表示已经排除过敏风险。
- 交叉接触、共用器具、酱料和供应商未标明的成分都无法判断。这里不判断食疗或医疗效果。生熟分开、海鲜、鸡蛋、剩饭和花生会给出操作上的提醒。
- 技能文字不能强迫模型每次都调用工具。模型没调用工具时，上述限制没有被程序执行。技能加载测试只检查说明文字，不是模型行为验证。

现有 Dream 仍可能把对话摘要写进工作区的 `USER.md`。`search_sessions` 仍可能读到其他会话里的用户和助手原文。美食工具自己不写这些共享记忆，也不能把它们关掉。首版不承诺端到端的会话隐私隔离。

## 测试说明

`tests/agent/tools/test_food.py` 不调用模型，直接检查工具：缺必要信息时追问什么、四人用量、采购换算和单位冲突、临时配方不返回做法、过敏不被口味或清除删掉、私聊元数据互不可见、群会话拒绝写入、分支复制当前偏好、无商家字段、不产生外部动作。

`tests/agent/test_builtin_food_skill.py` 只检查技能能被加载，以及说明文字里有这些边界。它不是一次真实模型对话。仓库里没有使用真实模型密钥做在线验收。
